# HT-风险官 · Round 1 独立盲写提案（异构降级位）

> 角色：假设与边界（前提不成立 / 合规 / 回滚 / 失败模式 / 假绿）。默认立场：**专挑"假设不成立"**。
> 纪律：默认怀疑其他人的推理，证据迫使才同意。本件不含"也许可能大概"，每条质疑带证据或推理链。
> 异构声明：本机 `~/.workbuddy/models.json` 实测只有 **1 个模型条目**（`deepseek-v4-flash`），无真模型异构；本件以 reasoning 档 + 最强差异化提示替代。

## §0 退一步

这个方案真正要解决的问题不是"要不要用 Python"，而是：**当前框架里有一批"只能靠自觉"的规则，在真实项目里反复漏执行，所以想把它们下沉为脚本闸门。** 但方案通篇默认了三个前提没验：① "下沉成引擎 = 更可靠"；② "零依赖手写 = 更可移植"；③ "单项目一轮的教训 = 框架级标配"。这三个都不成立时它失败的方式是**同一个**：引擎给出一个"绿"，而这个绿是假的——比提示词驱动的时代更危险，因为脚本绿会被无条件信任。**本框架已有一次实证：`six_layer_check.py` 自己的检查器说谎**（v3.19.0，注释剥离正则吃文件尾，既误报僵尸 handler、又漏报真问题）。所以本方案的第一风险不是"做不出来"，是"做出来以后，它说什么我们就信什么"。

## §2 我的三条最强质疑（K3 六要素）

### 质疑一 · "引擎化 = 更可靠"是方案地基，但检查器本身会说谎

- **问题**：22 条里没有一条定义"引擎**自己错了**怎么办"。整个方案的价值链是"规则下沉 → 脚本 Gate → 无条件信任绿"。而价值链的第一环已被证伪。
- **影响**：一旦某检查项稳定说谎，它会**同时**产生假红（真问题被噪音淹没、被忽略）与假阴（真问题被盖住）。且因为它是"脚本闸"，比提示词时代**更难被怀疑**——人会因为"脚本不会错"而跳过人工复核。这是**方案级**风险，不是实现细节。
- **等级**：**P0**（动摇地基）。
- **证据**：`SKILL.md` L38（v3.19.0）原文实证——`re.sub(r"/\*.*?\*/|^\s*//.*$", ..., flags=re.S|re.M)` 的 `re.S` 让行注释分支也吃换行，"从第一条行注释一路吃到文件末尾"，实测 `main/ipc.js` 第 148 行一条 `//` 之后 **24 个 handler 全消失**、`preload.js` 只剩前 11 条；**既误报"僵尸 handler"，也漏报真问题=假阴**。教训原话："**别急着改被测项目——可能是检查器自己在说谎**"。同批还发现 `_is_ts_project()` 缺失导致对非 TS 项目**结构性误报**。这是**84KB 的、最硬的**那个脚本。
- **建议**：把"检查器可信度"升为一级议题（见 §4 漏 1）。D-16 加入**反向 fixture（已知红必须报 FAIL）** + **定期独立复核**；并对每个存量检查项做一次"**已知坏样本回灌**"（拿历史真 bug 喂进去，看它到底报不报）。
- **证据增益**：能做到"每个 Gate 都被一条已知坏样本证明过它真的会红"，这是唯一能阻止"引擎化 = 假绿工厂"的办法。

### 质疑二 · "零依赖手写 LLM 层（D-11）"无网不可自测，且与方案自己的 D-04 直接冲突

- **问题**：D-11 要手写 SSE 解析 + 重试 + token 估算（约几百行新代码），但本机是**受限环境**，且手写 SSE 要处理的边界（JSON 被 TCP 分块切断 / `data:` 多行拼接 / `[DONE]` 终止 / 心跳保活帧 / `usage` 只在尾帧且流式需 `stream_options.include_usage`）**全部无法在无网环境真验**。
- **影响**：唯一的"自测"办法是 mock socket —— 而这**正好违反 D-04 自己刚立的规则**（"通道不可 mock，替身 = 伪造被测对象 = 假绿"）。于是 D-16 的"新命令必带自测用例"在这里**必然造假进度**：测试绿了，真调用照样可能挂。同时 stdlib 的证书/代理/超时在受限环境是已知坑源。
- **等级**：**P0**（新 bug 面 + 自测不可达）。
- **证据**：
  1. 本机实测 `runtime_probe.py` → `py_launcher=broken`、受限环境声明见 task-brief §2.7；
  2. `~/.workbuddy/models.json` 实测：**唯一模型 id = `deepseek-v4-flash`**，且条目含 `supportsToolCall / supportsReasoning / reasoning.defaultEffort` 这些**客户端字段**，`url` 指向 `https://api.deepseek.com/chat/completions`。
  3. **推理链**：`deepseek-v4-flash` 是 **WorkBuddy 注册表里的别名**，不是 DeepSeek 开放平台的公开 id（公开是 `deepseek-chat` / `deepseek-reasoner` 一类）。→ D-11 待定细节里"**必须打 `/models` 白名单核对**"这条护栏，**一跑就可能直接假红**（白名单里没有这个别名 → 引擎误拦一切调用）；若为避免假红而绕过核对，则"防 200 假绿"的护栏**真错**。两条路都是坑。
- **建议**：D-11 **不许在本轮直接落地**。先做一次性探针（下同），拿到三个事实再定形态：① `/models` 返回的 id 集合里**有没有**引擎要用的 id；② 流式帧的真实结构（`usage` 在第几帧）；③ 该 id 是否接受 `temperature`（关联 D-12③）。探针产物 = 真实响应 fixture，才是后面所有自测的**真基线**。
- **证据增益**：把"自建 SSE 客户端"从**拍脑袋决策**变成**有 fixture 支撑的决策**；也顺手验证 D-11 的"防 200 假绿"护栏本身能不能工作。

### 质疑三 · D-02/D-03 升格"框架级标配"违反方案自己的判据与既有规则（rule 5 / rule 47）

- **问题**：D-02 建议"**升格为框架级标配**（每个多窗口项目根自动建）"，D-03 建议"**换窗必做**"。而证据来源是**单个项目（伴学 P0）的一次实战**，候选件自己都写了"样本数 = 1 ✗，跨项目可复用性未经检验"。
- **影响**：框架已有 rule 5（`[事实]/[假设]` 分级）与 rule 47（**B1 试运行**，v3.17.0 新增）。绕过这两条把样本=1 的教训"标配化"，等于**用自己的规则打自己的规则**。后果：第二、三个项目被迫维护一个没证明有效的文件，若用户不填事件流，板子**失真**（原建议自己都承认"必须配硬约束"）——而失真状态**看起来是正常文件**，属于静默失效。
- **等级**：**P1**（流程性、可回退，但会累积成本）。
- **证据**：`讨论文档` §九-3 原文："**跨项目成立吗？——只在一个项目验证过的东西先标 `[假设]`；等第二个项目复现再升 `[事实]`**"；`蒸馏候选` §D 自陈"样本数 = 1 ✗，建议先在一个项目试运行（rule 47 的 B1 思路）"；`SKILL.md` L34 记录 rule 47 v3.17.0 已含"**B1 试运行**"机制。→ 方案作者自己写了判据，建议里却直接"升格标配"，**方案内部不自洽**。
- **建议**：D-02/D-03 一律**降级为 `references/` 可选模板 + `[假设]` 标签 + B1 试运行**；"标配化"作为第二项目复现**之后**的候选，不进本轮。
- **证据增益**：把"标配"决策从**情感驱动**变成**两个项目的数据驱动**，同时让判据 3 从"文档里的一句话"变成"真的被执行过"。

## §3 开源复用视角（风险官口径：什么能复用，什么必须自建）

1. **最该复用（零依赖内）· `unittest` 的 fixture 反例模式**：D-16 要的"已知红用例"，用 **stdlib `unittest`** 就能做，**不需要引 pytest**。每检查项配一对（已知绿 / 已知红）即可。判断：**适合**。
2. **最该复用（零依赖内）· 手写轻量 schema 校验**：D-12①的"解析失败不静默回退"用 `json.loads` + 手写字段/类型断言即可，**不引 pydantic**（引了既破零依赖，又给"校验器自己也有 bug"叠一层）。判断：**适合（自建轻量版）**。
3. **必须自建、不可复用 · 一次性探针脚本**：`/models` 白名单 + 流式帧结构 + `usage` 位置 + `temperature` 是否生效——**这是本机专属事实，任何开源件都给不了**。约 20 行 `urllib.request`。判断：**只能自建**。
4. **明确不要引入（反转性发现）· 不要接 LangGraph / Prefect / Dagster / Temporal / CrewAI 作编排内核**：本项目是**单人自用 + 零依赖优先**，"跨项目母板/多机协作"还是 P3 可选件（D-19）。引工作流引擎 = 用**平台化复杂度**换一个**尚未被证明存在的需求**，且会给引擎引入"框架自己也要学会的抽象层"，风险 > 收益。CrewAI 作为**思想来源**值得读，作为**运行时依赖**不值得。
5. **谨慎 · 上下文压缩库（LLMLingua 类）**：D-15 `compress` 要走 rule 83 三级级联，其中 LC1/LC2 **本就不花 LLM**（是机械操作），LC3 才花 LLM。引 LLMLingua = 大依赖 + 新模型，判断：**不适合**，LC3 先用一次 LLM 摘要即可。

## §4 我认为原文档漏掉的议题

1. **引擎自身的失败模式与回滚路径（漏 · P0）**：22 条全在讲"引擎能拦什么"，**没有一条**定义：引擎跑挂 / 卡住 / 给出错误裁决时怎么办？如何**降级回提示词驱动**？如何识别"引擎在骗我"然后人工接管？一个把信任全部搬进脚本的系统，**必须有回滚阀**，否则 v3.19.0 那种检查器说谎就没有出路。
2. **代码 ↔ 规则的漂移检测（漏 · P1）**：D-18 说"`SKILL.md` 是真相源"，但**没说怎么保证代码不漂移**。规则改了、代码没改（或反之），是 v3.19.0 同族故障。需一张 `子命令 ↔ rule 号` 映射表 + 改规则时 grep 引用面。
3. **有网/无网双模式边界（漏 · P1）**：本机是受限环境。P2 引入 LLM 调用层后，"无网时 design / route-error 的 LLM 兜底 / compress-LC3 全都不可用"——**应显式降级还是阻断**？这个边界没定，就会出现"无网环境静默跳过某步"的新假绿。

## §7 红队视角（没被质疑过的角落）

1. **默认值角落**：D-11 说"先 DeepSeek 一家"。但 `models.json` 的 `url` 是 `.../chat/completions`——**引擎若拼 base_url 时多/少一个 `/v1`，或在代理环境被重定向，会静默 404/200 空回**。默认 provider 的默认 base_url 必须**探针实测**，不许照抄。
2. **边界条件角落**：D-13 的"超预算即熔断"在 **usage 缺失**（流式未带 `include_usage`）时，`usage` 为 0 → **预算永远用不完 → 熔断永不触发**。这跟伴学"分母错 → 压缩永不触发（差 127 倍）"是**同一类架构级坑**（`context_compression.md` §0 原文警告过）。必须写死：**usage 缺失 = 记 `空` + 视为超限**（fail-closed）。
3. **失败路径角落**：engine 的 `init`（D-15）会**创建文件**。若它把"本机配置"（含 key）复制进项目目录，或在已存在文件时**静默覆盖**（幂等导入可见性 R-012 的教训："跳过必打日志"），就是合规 + 数据双失。**初始化必须只创建、不覆盖、且逐项打印动作**。
4. **依赖变化角落**：`sync_to_platforms` 依赖 banner 版本串（A10）；`cost_log.py` 依赖定长列（D-07 若乱塞会破）；`six_layer_check` 的 `--strict` 会把 SKIP 也算不通过。**任何一个 Gate 的依赖被上游改动，都可能让另一个 Gate 静默失效**——需要一张"Gate 依赖图"。
5. **反方假设角落**："**提示词驱动其实够用**"。22 条里没一条回答"如果不做引擎，只把 A 组 9 条写成规则，损失是什么"。本框架 v3.9→v3.20 十一版**全是提示词驱动 + 少量脚本**，且每版都收敛了实战问题——这本身就是**反方证据**：不引擎化也能迭代。不做"引擎 vs 只写规则"的对照，就无法证明 P2 的投入值得。

## §8 降级 vs 硬上 判定

**可以硬上（机制明确、可离线验证、风险低）**：
`D-05`（+计数）、`D-06`（+可寻址）、`D-07`、`D-12①②`、`D-15`（+回显）、`D-17`、`D-18`（+映射表）、`D-19`（先解并发）

**必须降级为 B1 试运行（单项目已验证 / 依赖用户行为 / 不可离线自测）**：
`D-01`（无测试手段的场景）、`D-02`、`D-03`、`D-09`（+计数）、`D-11`（**先探针，形态待定**）、`D-13`（先只告警，数据源改对后再开拦截）、`D-14`（表外置后可硬上，评测集标"覆盖不足"）、`D-21`（限模式）、`D-22`

**驳回原形 / 必须改再上**：
`D-08`（不同批改 sync 脚本就不许动 banner）、`D-12③`（驳回"分阶段温度"，改探针前置）、`D-20`（**当前已违规**，必须先修 `models.json` 明文 key 的暴露面）

## §9 一句话总结

**最可能让整个引擎化翻车的那一条假设是：「引擎（检查器）说真话」。** 方案的全部价值都建立在"规则下沉 → 脚本绿 → 可信"这条链上，而这个框架**已经有一次实证证明检查器自己在说谎**（v3.19.0：一个 `re.S` 让 84KB 的合规闸把 24 个 handler 全看没了，既假红又假阴）。如果这一条不成立，那么本轮造的每一个新 Gate，都在**以更可信的方式**生产假绿——比提示词驱动时代更危险，因为那时人还会怀疑，现在人不会。
