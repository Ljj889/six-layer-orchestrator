## §A 信息引导（K11，先答后审）

### A1. 我从我的视角看到、别人可能还没考虑到的关键信息

**（1）P2 的每一环都必须先回答两个问题，否则"分期"只是把风险推迟，不是隔离风险：①「这一环**离线**能不能验证？」②「这一环的 **Gate 语义由谁定义**？」**
后者是别人（含 HT2/HT4）都没点破的一个 P0 级暗雷：Round 1 我复核了 7 个脚本的 `main()`，证据如下——
- `checkpoint.py:112-134`：`main()` **成功路径直接 fall-through，没有 `sys.exit(0)`**；失败路径才 `sys.exit(1/2)`。
- `read_knowledge.py:117-137`：`main()` **永远 `return`（含"0 命中"）**，进程退出码恒为 0。
- `runtime_probe.py:135-160` / `validate_output.py:75-97`：`main() -> int` + `sys.exit(main())`（**只有这两个是"干净"的**）。
→ 结论：**"exit code 透传"不等于"Gate 语义"**。[S3] 说"main() 大多不调 sys.exit()"、[HT2] 说"main() 不可 import"，**两者都对、不矛盾**（详见 §B-质疑1 与 §C-[D-15]），合起来指向同一件事：**cli.py 若只做子进程转发 + 透传 returncode，会把"脚本没报错"当成"检查通过"——这正是它要防的假绿**。所以 cli.py 必须同时携带一份**「子命令 ⇒ gate 语义契约」**（哪个脚本、什么模式算 FAIL），这份契约本身要有反向 fixture。这是我 Round 1 漏掉、现在认为必须补进 P2 形状的一环。

**（2）"只增不删"（§七.5）会被 D-08 撞上，而 D-08 又反过来打断 D-09 的校验锚点——这是一条"改一处、断两处"的耦合链，必须在 P2 之前一次性画清。**
- [HT2 D-08 实测]：`sync_to_platforms` 的"逐目录文件数"校验，会因**新增 `CHANGELOG.md`** 而报红。
- [HT4 A10]：`sync` 的版本抽检依赖"banner 内版本串 ≥2 处"，**剪 banner = 同步 Gate 静默失效**。
→ 我 Round 1 只看到"D-08 要先于 D-09"的顺序问题，**没看到它会同时改动 D-09 的两条校验口径**。正确做法不是"先 D-08 再 D-09"，而是 **D-08 与 sync 脚本改造必须同批**（否则第二遍 sync 仍然红）。

**（3）P2 正确形状应是"按离线可验证性分环的依赖链"**——这一条我承认是 HT4 的轴 + 我把"独立收口 + 回滚"补上（见 §D-F1）。

## §B 交叉互审质疑（K3 六要素，≥2 条 P1+，点名到 HT）

### 质疑 1｜对 HT2：`subprocess 转发` 修好了"能不能调"，没修好"调完算不算通过"——Gate 语义仍然缺失

- **问题**：HT2 把 D-15 的解法定为"subprocess 转发器"（§1 D-15 / §2 质疑2），并补了 `encoding="utf-8"` 与 returncode 透传（§4 补充2）。但 [S3] 已实测：`checkpoint`/`cost_log`/`lifecycle` 的 `main()` **大多不 `sys.exit()`**；我进一步复核到 `read_knowledge.main()` **0 命中仍返回 0**、`checkpoint.main()` **成功路径无 `sys.exit(0)`**。→ **转发器忠实透传的，是一个"本身不表达失败"的退出码**。
- **影响**：cli.py 会成为**新的假绿中转站**——"Gate 跑过了、返回 0"，而实际检查根本没成立。这**恰好是你自己在 §6 要防的"`cli.py` 返回 0 但子脚本 FAIL 被吞"**，但你的"回显 returncode"并不能治它，因为**returncode 本身就是 0**。P2-α 的收口会变成"跑通即绿"，与 D-16 硬 Gate 的初衷（"防未完成混进来"）直接冲突。
- **等级**：**P1**（阻断 P2-α 收口）
- **证据**：`checkpoint.py:112-134`（成功 fall-through、无 exit(0)）；`read_knowledge.py:117-137`（0 命中仍 return）；[S3]"main() 大多不调 sys.exit()"；[HT4 §6 D-15]"cli 必须回显 returncode + 关键输出行；子脚本非 0 → cli 非 0"（**这条在 returncode 恒 0 时失效**）。
- **建议**：cli.py 增加一层**「子命令 ⇒ Gate 语义契约」**表（`{subcommand: {script, success_patterns, fail_patterns, exit_code_override}}`），对"退出码不表达失败"的脚本，由 **cli 层按输出模式 + 语义谓词**裁定返回值；该契约**每个子命令必须配一对反向 fixture**（已知绿 / 已知红），否则该子命令不许进 P2-α 的收口清单（复用 D-16 + HT4 的反向 fixture）。
- **证据增益**：把"转发器忠实"与"Gate 有效"解耦；避免 P2-α 交付一个**永远返回 0、因此不可能失败**的检查面。

### 质疑 2｜对 HT3：把"自测网"当作 P2 唯一的安全交付物，但 [S4] 证明**这张网里已经有一条假绿**

- **问题**：HT3 主张"P2 缩到 **cli 串联 + 自测网**"（§1 D-10 / 建议砍清单）。但 [S4] 实测：现有自测网的**用例 7 只跑 `bash -n`**——官方明说 `bash -n` 只解析语法，对引号/误用命令/可移植性"没什么可说的"，**这是形式通过而非实质通过**；同批还实测 **`assert` 可被 `-O`/`PYTHONOPTIMIZE` 静默关掉**。
- **影响**：把自测网当"最小、最安全、可先交付"的底座（HT3 的全部 P2 论证都建立在它之上）**前提不成立**——它当前：① 含至少 1 条假绿用例；② 若新增用例用裸 `assert`，整套网在 `-O` 下退化为空操作。**用一个不达标的网去背书"P2 仅做两件事就够"**，会把假绿**制度化**。
- **等级**：**P1**
- **证据**：[S4]"用例 7 是低门槛假绿教科书样本"、"`assert` 是可被 `-O` 静默关掉的空操作"；[S4]"fixture 实测 25 条，不是 24 条"（订正）；[HT3 §1 D-16]"自测用例是资产、成本主要记在 AI 头上"。
- **建议**：HT3 的最小 P2 应订正为 **「cli 串联（含 §B-质疑1 的 exit 语义契约）+ 自测网**返修**（隔离/重写用例 7 + 引入反向 fixture + 禁裸 assert + 离线可跑）」**；"自测网"作为交付物必须带"**已排除已知假绿**"的入库条件。否则这条最小路径交付的不是"安全底座"，是"带病的底座"。
- **证据增益**：把"最小交付"从"少做事"变成"**少做事但每件都真**"，避免 HT3 路线用规模换掉了正确性。

### 质疑 3｜对 HT4：以"并发基线未解"否决 D-02c **弱校验**，是拿"做不到强校验"否掉了"可做的中间态"

- **问题**：HT4 在 §1 D-02 主张"**驳回 (c)**——事件流'是否新增'校验的并发基线问题未解（A11），现在做 = 复制 render-silent-fail 的稳定误报老路"，§8 也把 D-02 整体列入"必须降级"。但 HT2 给出的 (c) 是**弱版**："**结构完整性 + 事件流 append-only（单调不减）校验**"（HT2 §1 D-02 原话）。
- **影响**：弱校验**不需要并发基线**——它不判定"该有几行"（那才需要基线 + 锁），只判定"行数不得减少 + 三段结构合法"。把它一并否掉，D-02 就退回**纯"文件存在性"**，而这**正是 HT4 自己在 §6 要防的假绿**（"板子建了、事件流一行不加，但文件存在 → 看起来有状态板"）。HT4 的否决把局面从一个**低成本可测的中间态**推向一个**更弱的终态**，方向与它自己的目标相反。
- **等级**：**P1**
- **证据**：HT2 §1 D-02"结构完整性 + append-only（单调不减）校验"；HT4 §5 A11（"事件流是否新增能被校验"的并发基线）；HT4 §6 D-02（"校验事件流行数而非文件存在"——**与它 §1 的否决自相矛盾**）。
- **建议**：拆两级——**P2-α 做弱校验**（结构 + 单调不减 + 离线可测，不承担"是否漏记"）；**P3 做强校验**（基线 + 锁，需 A11 先解）。并在规则里写死：**弱校验通过 ≠ 事件流完整**（防它自己变成新的假绿信号），把"是否漏记"显式留白。
- **证据增益**：把 D-02c 从"要/不要"的二元争论，变成"**先上能做的 30%，并诚实标注它不保证什么**"，避免因噎废食。

## §D 修订后的五个焦点结论（F1-F5）

### F1 · P2 的范围与形态 —— 三环结构（离线可验证性 × 依赖方向），每环独立收口 + 回滚 ｜**置信度：高**

**主张（替代我 R1 的"一条链一次做完"）：把 P2 拆成三环，环内串行、环间有门。**

- **P2-α「离线可验证的硬层」（先做，全部离线可测，可独立收口）**
  - 件：`cli.py` 转发器（**含子命令 Gate 语义契约**，见 §B-质疑1）｜`cli.py self-test` 总入口（stdlib `unittest`+`subTest`，1:1 平移 25 条 + 修用例 7）｜`route-error`（纯规则 + **表外置** + 5-10 条最小回归）｜`compress --lc1/--lc2`（机械层，**LC3 只留钩子**）｜D-12① 解析失败不静默回退｜`design` **仅当 schema 定稿**，否则不进本环。
  - **收口标准**：① `cli.py self-test` 全绿且 **`python -O` 下结果一致**（禁裸 assert）；② **每个子命令一对正/反 fixture**（已知红必须 FAIL）；③ 全程不触网。
  - **回滚**：全部为**新增文件**，删除即回滚，仓库真相源零改动。
- **P2-β「需真实 API 往返的层」（探针为前置门，真实往返为出口）**
  - 前置门：**一次性探针**（`GET /models` 白名单 + 一次非流式 + 一次流式），真实响应**入库为 fixture**——这是后面一切自测的真基线（[HT4 质疑二] 的诉求，我采纳）。
  - 件：`D-11` LLM 调用层（探针后定 (a) 手写 / (d) vendor `sseclient-py`）｜`D-12③` 档位（改 `reasoning_effort`）｜`D-13` (b)+(c)（数据源 = provider `usage`）｜`compress --lc3`。
  - **收口标准**：① **必须有一次真实 API 往返记录**；② 回归用**真 fixture**（非 mock）；③ **默认关闭**——无 key / 无网即降级回提示词驱动，且降级显式打印"未验证"并计入降级计数器（[HT4 A9]）。
  - **回滚**：β 全部新增 + 默认关闭 → 关开关即回滚。
  - **门**：探针若证"白名单无可用 id / 档位不可控" → 对应条目**降级或删除**，**不许留一个说谎的拦截项**。
- **P2-γ「推迟」（不阻塞 α/β 收口）**：真熔断 (a)、跨项目母板、用户极简入口页、平台化外壳。

**为什么这条同时满足"不空壳"与"可分期"**：α 的每一件都能**离线证明它真会红**（反向 fixture），所以不空壳；β 的每一件都有**前置门 + 出口证据**，所以不会"做完才发现验不了"；γ 被剥离，所以 α/β 的任何推迟**都不产生半成品**（这是 HT3"砍"的诉求的可满足版本）。我接受 HT2 的 4-6 轮工时画像，但把它**映射到 α（约 2 轮）/β（约 2-3 轮）**，而不是留成一个不可验收的大盒子。

### F2 · D-11 LLM 调用层形态 ｜**置信度：中**
**探针前置 + 默认 (a) 零依赖手写；把 [S2] 的 (d) vendor `sseclient-py` 设为"手写成本超阈值时的已尽调备选"；"零依赖"定义澄清为"允许 vendor 0 依赖单文件"。** 不定死 (a)/(d)，因为决定权应由探针 fixture 与手写工作量共同给出（HT3"先答有没有真实调用方"的前置问题**我部分接受**：β 的 (d)/(a) 之争在"探针答不出真实调用方"时可直接砍）。

### F3 · D-13 enforcement ｜**置信度：高**
**P2 只做 (b) 告警 + (c) 问人；真熔断 (a) 出 P2。数据源改 provider `usage`，分母从 `/models` 读（`context_window`/`max_output_tokens`），禁止用 API 上限做分母（防重犯 rule 83"分母错 127 倍"）；漏账 / usage 缺失 → fail-closed（记"空"并视为超限）。** 依据：[S1] 接口可读 + [HT2 三条前提实测不成立] + [HT4 A7/A12]。

### F4 · D-12③ 分阶段温度 ｜**置信度：高**
**接受驳回原形。"挂 D-11 之上"这一结构保留，但载体由 `temperature` 改为 `reasoning_effort`（或 `thinking.disabled`）；⚠️ 探针若证本机模型档位不可控 / 忽略该参数 → 直接删除该项，改为在 prompt 侧约束，绝不留一个"日志说冻了、实际没冻"的拦截项。** 依据：[S1]"Has no effect in thinking mode" + thinking 默认 enabled；[HT4 A4]。

### F5 · D-02 / D-03 是否升"框架级标配" ｜**置信度：中**
**降级：本轮不升标配。** 改 `references/` 可选模板 + `[假设]` 标签 + rule 47 B1 **单项目试运行**；第二项目复现后才谈升格。D-02(c) 以 **P2-α 弱校验**（结构 + append-only 单调）落地，并**显式留白**"弱校验通过 ≠ 事件流完整"。依据：[HT4 质疑三]（违反本方案自己的判据 3 / rule 5 / rule 47）+ [HT3 质疑二] + 蒸馏候选自陈"样本=1"；[HT2 D-02] + [HT4 A11] 决定 (c) 的形态。

## 一句话收尾

**我对 F1 的最终主张**：P2 = **按"离线可验证性"分三环（α 离线硬层 / β 需真实往返层 / γ 剥离），环内串行、环间设门，每环独立收口且回滚成本≈删文件**——α 用"反向 fixture"证明不空壳，β 用"探针前置 + 真实往返出口"证明不空跑，γ 剥离保证任何推迟不产半成品。

**与其他 HT 还剩的未消解分歧**：① 与 **HT2**——cli.py 到底"只透传退出码"还是要带**子命令 Gate 语义契约**（我认为必须带，否则 α 收口是假的）；② 与 **HT3**——P2 最小集能否把"自测网"当安全底座（我认为**必须先返修 S4 用例 7 + 禁裸 assert**，否则是把假绿制度化）；③ 与 **HT4**——"本机无网"是事实还是假设（若实测常在线，β 环应留在 P2 内而非外推，这条我已正式向 HT4 提问，**答案未到之前我把 β 的边界标为"待定 + 探针定夺"**）。
