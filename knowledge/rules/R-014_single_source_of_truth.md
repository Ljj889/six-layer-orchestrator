# R-014 一处信息散落多边 = 漏改静默

**当** 同一信息（规则 / 常量 / 字段 / 文案）**存在多个副本**（文档里多处、代码里多处、文档与代码各一处）时 → **易犯** 只改"**看得见的那一处**"——漏改的副本**不会报错**：断言红了还算好的（至少响），**更常见的是静默错**（字段读不出、脚本失配、文档与实现打架，全都悄无声息） → **护栏**：

1. **首选：收敛到单一真相源** —— 让信息**只有一个"家"**，其余位置**只引用、不复制**。本框架内已有三处可作范式：
   - **文档层**：规则 →「规则归属总表」（每条规则只一个家，其余只写指针）
   - **代码层**：通道名 / 目录名 → 两侧 import 同一常量文件（R-010 护栏 3）
   - **契约层**：生成物以契约为真相源（如"正文→抽取器→代码常量"，**禁手改生成物**）
2. **无法收敛时：必做"改一处 → 逐处核对"** —— 先列出**全部副本清单**再动手；改完对清单**逐条打勾**，不凭记忆"应该都改了"。
3. **给"多副本"配硬校验** —— 能 grep 的写成断言。范式：**加表/加列四处同步** `CREATE_TABLE_SQL` + `MIGRATIONS[n]` + `EXPECTED_COLUMNS` + `COLS`（**少加 COLS → SELECT 不带新列 → 静默读不出**）。
4. **改名 / 改常量类，先全库 grep 再动手** —— `grep -rn "旧值" --exclude-dir={node_modules,.git,dist,unpackage}`（**同时记得排除构建产物**，与 R-013 同源：构建产物里常留旧代码，会污染扫描结果）。

**本批两个实例（伴学·CMD24窗，可作范例）**：
- **例 A（改名散落）**：S0 断言硬编码 `partnerName === '小溪'` + 真机脚本 `s3-device.mjs` / `s3-gate45.mjs` / `s4-gate93.mjs` 写死"和小溪说话" → 默认名改**汀汀**后**同时失配**（1 断言 + 3 脚本）→ 一并改。
- **例 B（加列散落）**：db-ddl 加列只改了建表 SQL / MIGRATIONS / EXPECTED_COLUMNS → `repo.app.js` 的 `COLS` 没加 → `is_sample` **静默读不出（不报错）** → 补第四处。
