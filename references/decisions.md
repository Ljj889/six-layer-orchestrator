# decisions.md · 项目内决策编号制（Dxx）

> **版本**：v1.0 · 2026-09-30 · 来源：伴学 P0 C-2（蒸馏）+ 引擎层研讨 D-07 收敛
> **定位**：**推荐做法**（非硬性规则）。**独立文件**，**不进 `cost_log`** —— `cost_log` 是定长可 grep 行（rule 38/53），插词会破坏契约。
> **关联**：rule 84（跨窗口协作件）；ADR 两条纪律（**编号只增** / **取代不改写**）。

---

## 一、为什么要有这个文件

跨窗口/长周期项目里，"**为什么这么定**"是**最容易丢的信息** —— 代码只留"是什么"，契约只留"接口长什么样"，而**决策的理由、被否掉的选项、当时的约束**全在某个已经关掉的对话窗口里。

结果：新窗口看到一个"奇怪的实现"，要么改掉（其实是对的），要么照抄（其实是错的）。

---

## 二、编号纪律（ADR 两条）

1. **编号只增**：`D1`、`D2`、`D3` … 严格递增，**永不复用**。作废的号**留空**、不删（防"号跳了但没人知道为什么"）。
2. **取代不改写**：决策被推翻时，**不改原文**，而是新增一条并标 `Supersedes: D7` / 原条标 `Superseded by: D12`。**原文保留**，让后人看得到"当时为什么这么想"。

> 与框架全局 rule 编号同构（rule 13/15/17/25/26/30 留空不复用）。

**可 grep 要求**：决策号必须能被 `grep -E 'D[0-9]+'` 命中（写 `D12`，不要写 `D-12` / `#12` / `决策十二`）。

## 三、决策卡模板

```markdown
### D12 · <一句话决策名>
- **日期**：2026-09-30
- **状态**：`有效` | `已取代` | `作废`
- **Supersedes**：（可选）D7
- **背景**：<什么触发了这个决策？当时的约束是什么？>
- **选项**：
  - A. <选项 A>
  - B. <选项 B>
  - C. <选项 C>
- **选择**：B
- **理由**：<为什么选 B？被否的 A/C 各自为什么不行？>
- **影响面**：<哪些文件/模块/流程受影响？>
- **回退线（可选）**：<什么条件下应该切回来？一行即可>
```

**字段填不出的**：写 `待定` + 一行"什么信息到了才能定" —— **不许空着**（对应 rule 5 分级纪律：不确定就标注）。

## 四、放置与引用

| 项 | 位置 |
|---|---|
| 决策卡本体 | 项目根 `decisions.md`（或 `docs/decisions.md`） |
| 代码里引用 | 注释写 `// see D12` / `# decision: D12`（**不复制理由**，只留指针） |
| 交付报告引用 | 交付说明写"本轮新增 D14，取代 D9" |
| 框架级决策 | 归档进 `knowledge/decisions/`（ADR 桶），并在 `_index.md` 追索引（rule 54） |

---

## 五、反例（别这么做）

- ❌ 把决策写进 `cost_log.md` —— 破坏定长行契约，`cost_log.py summary` 会报不合规。
- ❌ 决策只写在对话里 / 只写在 commit message 里 —— 前者人看不到，后者 grep 不到理由。
- ❌ 推翻旧决策时直接改旧条目 —— 后人看不到"当时为什么这么想"，同一个坑会踩第二次。
