# R-016 定长分隔行账本解析禁用尾部相对下标（[-1]）

**当** 解析**定长分隔行**（`|` 分隔的定长账本 / 定段日志行，如 `cost_log.md`、`*.count.log`）时 → **易犯** 用**尾部相对下标**（`[-1]`）取"最后一段"当业务字段。一旦**加列/加段**（向后兼容的可选列），校验对象就**从指定列漂到末列** → 后果是**静默的双向失效**：原字段留空的行被**误报**、原字段填错而末列有值的行被**漏检**；最坏情形是该 Gate **每波照跑照出绿/红结论，而结论已无意义**（"脚本 Gate 空洞 PASS"新变体，与 rule 79 精神同型） → **护栏**：

1. **一律用固定下标**（`parts[5]` 而非 `parts[-1]`），并配 `len(parts) >= 6` 前置护栏。
2. **schema 扩列 = 全量复核解析点**：加一列/加一段，必须把该文件的**所有解析下标**过一遍（含 docstring 里的列语义说明与 `ALLOWED_*` 枚举）。
3. **必配混合列数 fixture 回归用例**：`6 列合规` / `6 列缺字段` / `7 列且第 7 列留空` / `7 列且第 6 列空而第 7 列有值`（双向漂移各一条）——**只有固定下标才能两组都过**。
4. **相对下标要"就地说明为什么安全"**：若确要用 `[-1]`（如 `splitlines()[-1]` 取命令输出尾行），必须写明**该序列不承载定长 schema**；否则视为违规。
5. **"看起来在跑"不等于"查得对"**：Gate 的退出码/绿红结论**不能作为校验对象正确的证据**——须有一条**已知坏样本**证明它真会红（rule 64 口径）。

**关联**：rule 79（产物断言 / 假绿家族）、rule 53（账本合规检查）、R-010（构建配置静默失效）、R-014（漏改一处静默）、R-007（僵尸能力：跑着但没有效力）、rule 64（能硬约束的不靠自觉）。

**【来源：2026-09-12 三审 HT-A/HT-C/HT-D 三方复现 · 2026-10-15 监理裁决另赋 R-016 并保留】**
