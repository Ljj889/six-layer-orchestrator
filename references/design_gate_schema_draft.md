## 二、schema 草案（**仅为示意，未经确认，不得据此实现**）

```json
{
  "version": "v1.0-draft",
  "confirmed_by": "<家俊确认后填>",
  "items": [
    {"id": "DS-01", "text": "框架设计图已产出并逐项确认", "evidence": "<路径>", "on_missing": "block"},
    {"id": "DS-02", "text": "每个功能/部分的代码骨架已产出", "evidence": "<路径>", "on_missing": "block"},
    {"id": "DS-03", "text": "数据迁移/语义变更策略已确认（rule 36）", "evidence": "<路径>", "on_missing": "ask_human"},
    {"id": "DS-04", "text": "未决项清单已登记（含『什么信息到了才能定』）", "evidence": "<路径>", "on_missing": "record"}
  ]
}
```

**`on_missing` 枚举**：`block`（阻断）/ `ask_human`（问人）/ `record`（记账放行）。

## 三、无论本件是否生效，都必须遵守的两条

1. **默认未启用**（HT-风险官追加，无异议）：`design_gate` 一旦实现，默认状态必须是"未启用"
   （与状态板模板同款先例 · D-02）。理由：它是**Gate**——一个判据来源不明、默认启用的 Gate，
   会在未知项目上**无差别拦人**；默认未启用最多是"该拦的没拦"，不会变成"不该拦的乱拦"。
2. **它不保证什么**（随件交付，来自开发文档 §4.2 L1b）：
   **「design 命令能跑」≠「设计锁定完整」**——rule 65 的流程含"边讨论边上网调研佐证"，命令行覆盖不到那一层。
