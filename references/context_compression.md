# 上下文压缩规格（Context Compression Spec）v1.0

> 引入：v3.18.0（2026-09-28）｜设计输入：借鉴「伴学 App」契约 §11 上下文压缩规格（三级级联 + 结构化摘要 + 阈值拆分），按六层框架语义重做
> SKILL.md 落点：**rule 83**
> 定位：**补 rule 40 缺的那一块**。
> - rule 81 管「排错过程的中途检查点」（每证伪一个假设即落盘）
> - rule 40 管「压缩**之前**必须落盘」（Pre-Compaction Flush）
> - **本规格管「压缩本身」**——压什么 / 压成什么 / 压后怎么验
>
> 三件套顺序：`rule 81 落盘 → rule 40 压缩前 Flush → 本规格执行压缩 → 压缩后复述测试`

---

## 0. 为什么需要（一条实测教训，别重犯）

「伴学」项目在压缩规格上踩过一个**架构级**的坑，直接照抄会重犯：

**原规格把触发分母设成 API 上限**（`0.7 × 1M = 700K`），而单次会话实际只有 ~5,500 token → **相差 127 倍 → 压缩永远不触发 → `summary` 永远为空 → 验收判据永远红灯**。

> **关键点：调 ratio 无论多小都没用——是分母错了。** 这条属于「静默失效」类故障：不报错、不崩溃，只是规格变成死代码。

**框架版的对策**：分母必须用**校准窗口**（按实测单轮/单 Wave 消耗推算），**不是**模型 API 上限。

---

## 1. 三级级联（顺序不可反，先廉后贵）

```
对话/状态继续增长 → 触发检查
  ↓
LC1 子 Agent 返回值压缩    回报 > N 行 → 只留「结论 + 证据指针」，全量落盘     （不花 LLM）
  ↓（仍超）
LC2 已消费输入淘汰          标记已被消费的中间输出为可丢弃                  （不花 LLM）
  ↓（仍超）
LC3 结构化摘要              更早的对话/状态 → 框架版六字段摘要 → 存 progress.json（唯一花 LLM 的一层）
```

**纪律**：前两层不花 LLM 调用，LC3 贵。**不能等撑爆了才压**；先截断、再淘汰、最后才摘要。

**LC1 的具体做法**（框架特有，也是最大 token 消耗源）：
- 子 Agent 回报默认**只回「结论 + 证据指针」**（文件路径 + 行号@commit），全量报告落盘到 scratchpad/模块目录；
- 呼应 rule 28（大代码落盘 + 紧凑 manifest）与 rule 40 注入三级策略（L2 混合：内联摘要 ≤20 行 + 路径指针全文）；
- 审查员按需读文件，**不靠对话里的全量粘贴**。

**LC2 的具体做法**：
- 框架里子 Agent 之间**不直接对话**（数据由调度器中转，rule 16）→ **中转动作完成 = 该条回报即可标记可淘汰**；
- 标记动作本身不花 LLM，且**标记 ≠ 删除**（磁盘上仍可查，只是不再进上下文）。

## 2. 触发判据（分母是命门）

```js
// 校准窗口：按实测推算，不用 API 上限
export const TRIGGER_RATIO = 0.75;   // 触发比
export const RESERVE_RATIO = 0.30;   // 保留比（最近 N 轮/Wave 原文不压）

// 触发：估算用量 > 校准窗口 × (1 − RESERVE_RATIO)
```

| 项 | 规格 |
|---|---|
| **分母** | **校准窗口**（实测单轮/Wave 消耗 × 期望保留轮数）。**禁用 API 上限做分母**（见 §0） |
| **粗判据（沿用 rule 40）** | 单任务目标 < 2,000 行；> 5,000 行必须压。**本条给的是细判据（分母 + ratio）** |
| **自然边界优先** | **Wave 结束 / 模块验收通过 / 排错定位根因** —— 这些是天然压缩点，优先在这些点压，而非"满了才压" |
| **硬上限兜底** | 超 `0.9 × 校准窗口` **立即压**，不等边界（防连续排错撞上限直接报错） |
| **校准回写** | 每次实际用量（如 `usage.prompt_tokens`）回写，**定期校准**校准窗口数值；数值写死时须带**出处 + 校准日期** |

## 3. 压缩产物 = 框架版六字段摘要（存 progress.json）

```json
{ "phase"      : "当前 Phase / Wave",
  "modules"    : "各模块三态（引用 progress.json 字段，不重述）",
  "ruled_out"  : "已排除的假设（rule 81 排错检查点，逐条）",
  "top_suspect": "当前最大嫌疑（排错时才有）",
  "open_items" : "未验证项清单（rule 42）",
  "next"       : "下一步计划（含负责的子 Agent 角色）" }
```

**三条硬纪律**：

1. **摘要不替代 progress.json。** `progress.json` 是**结构化事实源**（机读、三态、可核验）；摘要是「给下一个 Agent 的交接单」。**冲突时以 progress.json 为准。**
2. **指针优先。** 摘要里凡涉及文件/代码，必须带 **路径 + 行号@commit**（rule 5 分级纪律延伸到摘要；无 commit 锚的行号会漂移误导）。
3. **不得转述子 Agent 的原话/中间输出**——只留**结论 + 证据指针**。理由：转述必失真（呼应 rule 40 注入三级治理的 T2 目标）。

**为什么不直接用「任务型模板」或「伴学五字段」**：框架的压缩单位是 **Phase/Wave/模块**，不是"一轮对话"。字段必须能被下一个 Agent 直接接上（它是"交接单"，不是"给用户的报告"）。

## 4. 压缩后校验（不做 = 压缩可能白做）

压缩后**先跑一次「复述测试」**：

> 仅凭 `progress.json` + 六字段摘要，能否复述出 **`phase` / `ruled_out` / `open_items` / `next`** 四项？

- **能** → 放行继续；
- **不能** → 说明该落盘的没落盘，**回退重压**（补落盘后再压一次）。

这对应 rule 40 的「压缩后校验落盘成功才继续」——**校验不是可选项**。

---

## 5. 失败降级（压缩失败 ≠ 任务失败）

- LC3 摘要生成失败 → **重试 1 次** → 仍失败则降级为「**只保留最近 N 轮 + progress.json 指针**」继续；
- **禁止**因压缩失败阻断主流程（压缩失败 ≠ 聊天/开发失败）；
- **禁止静默降级**：降级动作必须在 `cost_log.md` 记异常类型列（rule 53 第 6 列 = `截断`/`空`/`非法JSON`）。

## 6. 与现有规则的分工（不重叠、不替代）

| 规则 | 管什么 | 与本规格的关系 |
|---|---|---|
| **rule 81** 长排错会话检查点 | 排错**过程中**：证伪即落盘 + 3 轮强制小结 | **本规格的前置**（保证压缩前事实已固化） |
| **rule 40** 上下文管理 | `>5,000 行必须裁剪` + **压缩前落盘钩子** | 本规格是它的**执行细则**（压什么/压成什么） |
| **rule 39** Checkpoint 三态 | `progress.json` 三态 + 预期产物清单 | 本规格的**事实源**（摘要引用它，不重述） |
| **rule 42** 未验证项清单 | 交付必须列未验证项 | 摘要 `open_items` 字段直接引用它 |
| **rule 56** 心跳报告 | 长轮询每轮重读约束刷新上下文 | 互补：心跳防**污染**，本规格防**膨胀** |
| **rule 70** Wave 级复盘 | 每 Wave 后落盘复盘卡 | 天然压缩点之一（Wave 边界） |

---

## 7. 验收判据（可检查，不靠感觉）

S1. 压缩前后：仅凭 `progress.json` + 摘要能复述 `phase / ruled_out / open_items / next` 四项（复述测试通过）；
S2. 摘要中每条文件/代码引用**都带** 路径 + 行号@commit（可 grep 判定：`grep -E ':[0-9]+@[0-9a-f]{7}'`）；
S3. 压缩发生后，子 Agent 派发说明仍然完整（不依赖被丢弃的对话内容）；
S4. 压缩失败/降级在 `cost_log.md` 有记录（异常类型列非空）。

**任一不通过 = 压缩规格未落地**（不是"大致可用"）。

---

## 8. 已知边界（诚实标注）

- 校准窗口的**具体数值**需按项目实测校准，本规格只给方法与比值，**不给魔法数字**；
- 本规格为**提示词驱动**（当前 WorkBuddy/CodeBuddy 引擎层形态）；平台引擎层（编排 B）落地时应实现为**压缩函数的强制前置钩子**（先落盘 → 再压缩 → 复述测试，三步硬串）；
- 「复述测试」目前由调度器自证，**尚无脚本化实现**——登记为待硬化项。
